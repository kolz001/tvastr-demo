tvastr · how it works

Autonomous code-remediation agent — from a GitHub bug to a verified fix, benchmarked against the maintainer's own PR.

local (Ollama) — sensitive data cloud (Claude) — reasoning rule-based — no LLM PR-benchmark feature

tvastr watches a stream of failures (GitHub issues or production logs), clusters the recurring ones, traces each to its root cause, and opens a fix PR. The privacy boundary is real: sensitive data is parsed by local models and redacted before any cloud call. Its headline trick is self-evaluation — when a human PR already exists for the bug, the agent grades its own fix against that PR as ground truth. Click any stage below to see what runs it.

1 · Ingestion

rule-based

The only contract with the outside world is JSONL of LogEvent. Sources plug in behind a LogSource protocol: bundled samples, stdin, a Grafana Loki query, or a GitHub bug tracker.

For the demo, each issue becomes zero-or-more LogEvents: a crashing bug yields the real exception class; a non-crashing [Bug]: report becomes a synthetic UnexpectedBehavior event; a feature request yields nothing (the UI shows the skip reason).

Files that run this
  • src/tvastr/ingestion/github_issues.py— issue → LogEvent(s)
  • ingestion/loki.py, stdin_source.py— other sources

2 · Detection & clustering

rule-based

Events are clustered by a fingerprint: the message is normalized (UUIDs, hex, ids, numbers, quoted literals → placeholders) so the same failure with different runtime values collapses into one pattern. No LLM — it's a stable SHA over service | exception | normalized message.

A threshold engine then selects patterns that recur often enough to be worth acting on (the live "apply fix" path bypasses this and acts on the one issue you picked).

Files that run this
  • src/tvastr/detection/clustering.py— fingerprint + cluster
  • detection/threshold.py— recurrence selection

3 · PII redaction — the privacy boundary

local boundary

This is the hard constraint real log systems have: logs contain secrets and PII that must not leave the local boundary. Before anything is escalated to the cloud, it passes through a conservative redactor — API keys, bearer tokens, AWS keys, credentialed URLs, emails, IPs — each replaced by [REDACTED:LABEL].

Order matters: CREDENTIAL_URL runs before EMAIL so a credentialed URL is captured whole before EMAIL claims its user-info. Every redaction is recorded in the routing decision.

Files that run this
  • src/tvastr/pii/redaction.py— redact() / contains_pii()

4 · Hybrid LLM routing

localcloud

Each unit of work is a TaskType routed to the right tier: log parsing and summarization stay local (Ollama) because they touch raw, sensitive data; root-cause reasoning, fix generation, PR analysis and the fix-vs-PR comparison go to the cloud (Claude) — but only after redaction.

Every call produces a RoutingDecision recorded in the audit trail, so you can prove raw sensitive data never crossed the boundary.

Files that run this
  • src/tvastr/llm/router.py— HybridRouter + TaskType
  • llm/claude.py, local.py— backends (+ mocks)

5 · The agent (LangGraph state machine)

cloud reasoning

Each selected pattern runs through a StateGraph. The ReAct-style decision point is the confidence gate: the agent only acts (generates a fix and opens a PR) when its root-cause analysis is confident enough; otherwise it escalates to a human via notification.

The benchmark feature inserts one node — compare_to_pr — between fix generation and the PR draft, so every acting run self-grades against the upstream PR.

Files that run this
  • src/tvastr/agent/graph.py— graph topology + nodes
  • agent/state.py, agent/tools/— state + tools

6 · Investigate & root-cause

toolscloud

The investigate node gathers evidence: it extracts suspected files from a stack trace, or searches the codebase for the exception type, then retrieves those files. The reason_root_cause node hands that context to Claude.

Confidence tracks evidence strength — a stack trace pins the file (0.8), a search hit is circumstantial (0.6), nothing found escalates (0.3). The gate threshold is 0.5, so honest weak evidence routes to a human.

Files that run this
  • agent/graph.py— _investigate / _reason_root_cause / _confidence_gate
  • agent/tools/code_retrieval.py, github_search.py

7 · Fix generation

cloud

Claude returns a structured JSON fix proposal. The tool turns each search/replace into a real FileChange against the retrieved source and computes a unified diff — so what you review is an actual patch, not prose. If parsing fails, it falls back gracefully rather than crashing the run.

Files that run this
  • src/tvastr/agent/tools/fix_generation.py— generate_fix()
  • domain/models.py— FixProposal / FileChange

8 · PR discovery & analysis

discovery (no LLM)analysis (cloud)NEW

For each loaded bug, tvastr finds the PR that addresses it. Timeline cross-reference links are sparse in the wild, so discovery uses the GitHub Search API (repo:X type:pr <issue#>) and ranks candidates: open > merged > closed, then recency. Cheap, cached, no LLM.

The PR's diff is fetched (capped at 30 files / 1500 lines) and the top issues get a one-call Claude analysis: does this PR address the issue, what's the approach, which files. This is the ground truth the benchmark needs.

Files that run this
  • src/tvastr/analysis/pr_discovery.py— discover_pr / fetch_pr_diff
  • analysis/pr_analysis.py— analyze_pr
  • api/routes/pr.py— /api/issue-pr, /api/pr-analysis

9 · Agent-vs-PR benchmark ★

cloudNEW — the headline

This is the point of the whole thing. Once the agent has produced its own fix and an upstream PR exists, the compare_to_pr node grades the two. The maintainer's PR is treated as a ground-truth oracle: did the autonomous agent reach the same root cause and touch the same code a human did?

File overlap is computed deterministically in code (set arithmetic on the two change lists) — never trusted to the LLM. The LLM only judges root-cause agreement, functional equivalence, and the verdict.

match partial divergent
Why it matters: every acting run self-reports against a human baseline and streams a verdict card into the live timeline — turning a demo into a measurable eval of the agent's quality. A failure to parse degrades to divergent / 0.0; no PR found emits benchmark.skipped (never hidden).
Files that run this
  • src/tvastr/analysis/fix_comparison.py— compare_fix_to_pr
  • agent/graph.py— _compare_to_pr node

10 · Verify-fix loop

sandboxcloud

A diff isn't a fix — the loop closes only when the failure is shown to go away. tvastr synthesizes a reproducer, runs it in a sandbox (Docker --network=none --read-only --cap-drop=ALL, subprocess fallback), then baseline → apply patch → re-run, with an optional scoped-test regression check.

It emits an explicit oracle verdict — verified_via_reproducer, verified_via_scoped_tests, or still_broken / regression / no_repro — and never quietly hides a failure.

Files that run this
  • src/tvastr/verification/verifier.py— the loop + verdict
  • verification/repro.py, sandbox.py

11 · Output: PR · audit · live stream

orchestration

The pipeline ties it together and instruments every step. A draft PR is opened (fork-only by default; the UI is dry-run and never opens a real PR without opt-in), an AuditRecord is saved, and a Slack notification fires.

Every moment is a PipelineEvent fanned out to a Queue (live SSE for the triage UI at /app) and a JSONL file (data/runs/<run_id>.jsonl) so runs replay later. The benchmark.compared event renders as the match/partial/divergent verdict card.

Files that run this
  • src/tvastr/pipeline.py— end-to-end orchestration
  • events.py— PipelineEvent + sinks
  • api/routes/run.py, templates/app.html— SSE + UI
